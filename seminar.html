05 · NETWORKING · SM2.0 — 2.4

The OSI model — click a layer

00:25 – 00:30

Layer 7 · Application

Services to applications, user requests, data formatting. HTTP, DNS, SMTP.

Security: this is where phishing and bad authentication live.

Layer 6 · Presentation

Converts between formats, and handles encryption, decryption and compression.

One machine sends Unicode, another ASCII — this layer translates.

Layer 5 · Session

Establishes, manages and terminates conversations. Join an online class → session created; leave → suspended; rejoin → re-established.

Security: session hijacking targets this layer.

Layer 4 · Transport

Splits data into segments, guarantees delivery and order (or deliberately does not), and controls flow. TCP, UDP.

Security: port scanning, SYN floods, UDP abuse.

Layer 3 · Network

Logical addressing and routing — choosing the path between networks. IP, ICMP, ARP.

Security: IP spoofing, routing attacks, address scanning.

Layer 2 · Data Link

MAC addressing and frames, for devices on the same local network. Adds header and trailer to make a frame.

Security: MAC spoofing, ARP attacks, switch attacks.

Layer 1 · Physical

Bits, signals, cables and radio — actually putting the data on the medium.

Security: cable tapping, interference, physical access.

Remember

The OSI model is not directly implemented — real systems run TCP/IP. OSI is a conceptual map used for troubleshooting: work down the layers to find where it breaks.

TIME00:25 – 00:30 · 5 minutes · SM2.0 serial 2.4

WHAT TO EXPLAINGive the order out loud first, twice. Then click down the layers rather than reading them — one layer, one job, one security note. Use the course's own troubleshooting example: a website is not loading; is it the cable, the IP address, the application, or the server? Without a structured model you are guessing.

EXAMPLETwo from the course. Presentation: one computer sends Unicode, another uses ASCII — this layer converts. Session: an online class — join, leave, rejoin, meeting ends.

EXAM FOCUSLayer order is the single most likely OSI question. Then: "which layer does encryption?" (Presentation), "which layer uses MAC addresses and makes frames?" (Data Link).

Press Enter to build the connection, then lose a packet. SYN — the client asks to connect. This begins the three-way handshake. SYN-ACK — the server acknowledges and asks whether the client is still there. ACK — the client confirms. Connection established; data can flow. Data flows reliably and in order. Every segment is accounted for. A segment is lost. TCP notices and retransmits it — nothing ends up missing. Press Enter to fire packets with no setup at all. No handshake, no acknowledgement. Packets are simply sent — that is why it is fast. Packet 3 is lost. There is no mechanism to notice. Nothing is retransmitted. The stream continues with newer data — a late packet is worse than a lost one.

Why it matters for security

TCP gives the defender state to track, filter and log. UDP has none — which is why it is abused, and why it cannot simply be blocked: DNS, VoIP and streaming depend on it.

TIME00:36 – 00:44 · 8 minutes · SM2.0 serial 2.5 · the flagship demo of the session

WHAT TO EXPLAINRun TCP all the way through first — handshake, ordered data, then lose a segment and watch the retransmission. Then switch to UDP and run it again. The contrast is the lesson: TCP has state, so it can be tracked, filtered and logged. UDP has no state at all. Do not read the table at the bottom — they have just watched it.

EXAMPLEAsk the room which they would choose for a voice call (UDP — a late packet is worse than a lost one) and for a bank transfer (TCP — every byte must arrive, in order).

12 · CYBERSECURITY · SM2.0 — 2.1

The CIA triad

01:07 – 01:14

Click a leg

Only authorised people can see it. Controls: encryption, access control, limiting who has a login.

Damaged when: a customer address leaks, or a login is guessed.

It stays accurate and unaltered. Controls: checksums, digital signatures, controlled permissions.

Damaged when: an invoice total is silently altered.

It is accessible when legitimately needed. Controls: redundancy, backups, defences against floods.

Damaged when: a warehouse system is offline for six hours.

Remember — tension, not a checklist

Strengthening one leg can damage another. Locking a system down so hard that staff cannot work damages availability — and pushes people to unsafe workarounds, damaging confidentiality too.

EXAM CHECKPress A / B / C / D — then ENTER to reveal

A system is configured so strictly that legitimate staff can no longer work. Which leg is damaged?

C — Availability. A control that stops legitimate users reaching data damages availability, even though nothing was stolen or altered. Authentication is not a leg of the triad at all.

Hover, do not click. The true destination is frequently not what the text claims.

A mismatch worth noticing. An urgent personal message that opens with "Dear Customer" is not personal at all.

The classic delivery mechanism. An invoice or archive you were not expecting is exactly how the trojan reached the victim in the course's incident.

PHISHING · SOCIAL ENGINEERING

Urgency plus a link. No technical flaw is exploited — the attack targets judgment, so the correct response is procedural: do not click, do not reply, report it.

MFA — and its limit

More than one family means a stolen password alone is not enough. Not unbreakable: MFA fatigue floods you with approval prompts hoping you tap approve. An unexpected prompt deserves the same pause as a suspicious email.

EXAM CHECKPress A / B / C / D — then ENTER to reveal

A badge correctly identifies an employee but lets them into a room they should not enter. What failed?

B — Authorization. The badge proved identity, so authentication worked perfectly. The failure is in what that confirmed identity is permitted to reach.

EXAMPLEThe badge story from the course: a former employee's badge was never deactivated. EXAM FOCUSThis distinction is heavily examinable. Also know: encryption protects confidentiality, not availability or integrity; the key matters as much as the algorithm; a padlock means encrypted, not legitimate.

Incident response — five stages
0/5
1Identify 2Contain 3Eradicate 4Recover 5Lessons learned
Press Enter. This order matters. Identify — notice something is wrong. The stage an ordinary employee controls. Contain — isolate the system. Disconnect it from the network first. Eradicate — remove the actual cause once spread has stopped. Recover — restore safely, verifying the system is clean. Lessons learned — and remember: speed of containment decides the outcome, not a perfect later response.
